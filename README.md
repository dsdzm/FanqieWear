# 书阁 · 手表版（FanqieWear）

一个跑在 **Wear OS / Android 8+ 手表**上的免费小说阅读器，纯 Jetpack Compose + Wear Compose 实现。
含**分类书库、搜索、书架、阅读历史、离线下载、TTS 听书**，支持**多书源自由切换**。

> 当前默认书源是**笔趣阁**（免登录、正文完整）。番茄源的登录链路走字节 Passport，
> 手表端拿不到完整正文，暂时降级为备用源——代码保留着，登录修好后在设置里切回去即可。

v1.5 主要变化：

- 抽出统一书源层 `BookSource` + `SourceRegistry`，页面不再直接依赖某个站点
- 新增免登录书源**笔趣阁**，搜索 / 分类 / 详情 / 目录 / 正文全通
- 设置 → 网络与书源：**选中即切换**，每个源标注能力与限制，支持**一键连通性检测**
- 书架、阅读历史、继续阅读都会记住**这本书来自哪个源**，跨源不会串
- 番茄源降级为可选备用源，七猫源保留（只到目录）
- **v1.6**：语音引擎内置，eSpeak NG 与中文数据随 APK 发布，不再让用户下载任何引擎

## 二、笔趣阁：实测结论

选它当默认源的原因很简单：**全链路免登录**，且页面结构稳定到可以用正则解析。

| 能力 | 路径 | 说明 |
|---|---|---|
| 搜索 | `POST /s.php`（`type=articlename&s=关键词`） | 服务端渲染 HTML |
| 详情 | `GET /book/{id}/` | `<h1>` 书名，`.xinxi` 里有作者/类型/状态/最新章节 |
| 目录 | `GET /newbook/{id}/` | `<ul class="info">` 是全量正序章节 |
| 正文 | `GET /chapter/{bid}/{cid}.html` | `<div id="txt">`，`<br>` 分段 |
| 分类 | `GET /sort/{分类}_{页码}/` | 页码从 1 开始，8 个分类 |

实现细节（`data/BiqugeApi.kt`）：

- 正文清洗：`<br>` 转段落，逐行丢掉站点插入的广告与推书行（"一秒记住"、"笔趣阁"、"最新网址"…）
- 上一章 / 下一章直接从页面导航区解析，不依赖目录下标，断章也不会错位
- 详情与目录缓存 2 分钟，请求间隔 200ms，避免给站点压力
- 章节 `itemId` 只取数字串（如 `13964879`），可以直接当离线文件的名字

## 三、番茄源（备用）：接口实测

开发时把 GitHub 上的方案（`mcp-server-fanqie`、`fanqie-api`、`fanqie-dl`、`PyFQWeb`）和真实接口都跑了一遍，
结论如下（2026-10 实测）：

| 能力 | 接口 | 是否需要签名 | 返回编码 |
|---|---|---|---|
| 搜索 | `novel.snssdk.com/api/novel/channel/homepage/search/search/v1/` | 否 | 明文 |
| 书籍详情 | `fanqienovel.com/page/{book_id}` HTML 内 `__INITIAL_STATE__.page` | 否 | 明文 |
| 目录 | `fanqienovel.com/api/reader/directory/detail?bookId=` | 否 | 明文 |
| 章节正文 | `fanqienovel.com/reader/{item_id}` HTML 内 `__INITIAL_STATE__.reader.chapterData` | 否 | **字体加密** |
| 推荐流 | `fanqienovel.com/api/rank/recommend/list` | 否 | 明文 |
| 分类榜单 | `fanqienovel.com/api/rank/category/list` | 否 | **字体加密** |

两个关键发现：

1. **字体反爬可以离线还原。** 番茄把常用字替换成私有区字符（U+E000–U+F8FF），用自定义 woff2 渲染。
   本项目通过字形比对（Pillow 渲染 + Noto Sans CJK 匹配 + 匈牙利算法保证一一对应）还原了 362 个码点，
   生成 `app/src/main/assets/fontmap.json` 内置到 App 里，**运行时零请求、纯本地解码**。
2. **不同页面用不同字体。** 榜单页字体映射稳定，书库页是另一套，所以番茄源也没用书库接口。

### 为什么番茄暂时不能用

番茄的登录不是自己的页面，而是字节 **Passport（muye SDK）**。实测：

- 直接 `GET /passport/web/get_qrcode/` → `{"error_code":22,"description":"非法应用"}`
- 带 `aid=1967` → `{"error_code":16,"description":"该应用无权限"}`
- 首页加载了 `secsdk-lastest.umd.js`、`byted_acrawler`，`X-Argus / X-Gorgon / X-Bogus`
  由脚本运行时生成，和 aid、URL、时间戳、ttwid 绑定

在手表客户端复刻这套签名既不可维护，也等于绕过平台风控，所以没有做。
**未登录只给每本书前 10 章左右试读**，第 11 章起 `chapterData.content` 只剩约 200 字、
`isChapterLock=1`，这不是解析 bug。

App 里保留了两条合规路径（在设置里把书源切到「番茄小说」后才会出现入口）：

1. **网页登录**：内置 WebView 打开官方登录页，用户自己登录，完成后从 `CookieManager` 取 Cookie
2. **粘贴 Cookie**：手机浏览器登录后复制整段 Cookie，粘到手表输入框

Cookie 只存本机 SharedPreferences，不上传。

## 四、七猫：只到目录

七猫网页端被阿里云 WAF 拦死（滑块验证），只能走 App 端接口。签名算法已跑通：

```kotlin
// 参数按 key 排序拼 "k=v&k=v"，末尾拼固定密钥做 MD5
sign = md5(params.sorted().joinToString("") { "${it.key}=${it.value}" } + "d3dGiJc651gSQ8w1")
```

搜索、详情、目录可用；正文接口 `chapter/content` 一直返回「参数错误」，
还需要 App 端才会生成的字段，所以这个源只支持浏览。UI 里会直接提示，不会静默失败。

## 七、安全区与小屏适配

320×320 在 2x 密度下只有 **160dp 宽**，圆屏两侧还会被弧线切掉，所以边距不写死：

- `rememberDeviceDims()` 按 `屏幕宽度比例 × 安全区档位` 算出行内边距
- **安全区 5 档**：自动 / 紧凑 / 标准 / 宽松 / 最宽，设置页带形状预览
- **界面缩放 4 档**：字号、卡片高度、图标位一起等比放大
- 首页/设置用全宽胶囊卡（高 52dp 起），最小触控区 ≥48dp

### 设置清单（8 组）

| 分组 | 可调项 |
| --- | --- |
| 阅读外观 | 字号（4 档）、行距（4 档）、段间距、6 种背景、6 种字色、两端对齐、屏幕常亮 |
| 阅读操作 | 阅读方式（滚动/翻页）、翻页动画、表冠翻章、表冠速度、自动下一章、预加载、启动续读 |
| 界面与安全区 | 主题、主题色（5 套）、界面缩放（4 档）、安全区（含预览）、列表封面 |
| 语音听书 | 语速、音调、试听 |
| 下载与存储 | 缓存统计与清理 |
| **网络与书源** | **书源切换、能力说明、连通性检测、番茄账号** |
| 交互 | 震动反馈、边缘滑动返回 |
| 关于与支持 | 版本、免责声明、恢复默认 |

全部写入 `SharedPreferences`，通过 `StateFlow` 驱动 UI，改完即生效。

### 正式签名

`app/build.gradle.kts` 支持一把独立的 release 密钥，v2 + v3 同时启用：

1. 放好 `keystore/shuge-release.jks`
2. 在 `local.properties` 里写 `SHUGE_STORE_PASSWORD` / `SHUGE_KEY_ALIAS` / `SHUGE_KEY_PASSWORD`

密钥文件与密码都在 `.gitignore` 里，不会进仓库；没有 keystore 时自动回退到 debug 签名，
别人 clone 下来照样能构建，只是不能用于发布。

> 换签名后无法覆盖安装旧包（证书不同会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`），
> 需要先卸载。卸载会清空本机的书架与进度。

### 双签名产物（每次发版固定）

```bash
tools/package-release.sh
```

一次构建出两个包，`dist/` 下：

| 产物 | 证书 | 用途 |
|---|---|---|
| `FanqieWear-v<ver>-release.apk` | `CN=Shuge Wear`（`keystore/shuge-release.jks`） | 普通安装 |
| `FanqieWear-v<ver>-testkey.apk` | AOSP `testkey`（`CN=Android, O=Android`） | 定制系统 / 系统分区 / 需要 testkey 信任链的场景 |

两包证书不同，**不能互相覆盖安装**，切换前先卸载。脚本发现 `keystore/testkey/` 缺失时会自动从
AOSP 镜像拉取，仓库里不放任何私钥文件。


## 九、离线下载

书籍详情页 →「下载全本」或「前 50 章」，整本缓存到手表本地（`filesDir/downloads/<bookId>/`），
阅读时优先读本地文件，断网也能看。下载元数据里记了**书源**，离线打开时按原源走。
下载在应用级协程里跑，切页面不中断，可在「下载与缓存」页看进度、取消、删除。

## 十、语音引擎：内置，装完就能听

早期版本让用户去装 eSpeak NG 的 APK 或系统语音包，手表 ROM 一精简就哑了。
v1.6 起引擎直接编进 APK：

| 组成 | 说明 | 体积 |
|---|---|---|
| `libespeak-ng.so` | espeak-ng 1.52.0，NDK 交叉编译，arm64-v8a + armeabi-v7a | 705K / 487K |
| `libespeakng-jni.so` | JNI 桥，`espeak_Synth` 收 PCM 交给 AudioTrack | 8K |
| `assets/espeak-ng-data/` | 中文语音数据 + 英文词典，从 19MB 裁到只留 cmn/en + 音素表 + 音色 | 2.8MB |

关键实现：

- `EspeakEngine` 首次使用时把 assets 里的数据解到 `filesDir/tts/`，用版本号文件避免每次启动重解；
  解压后逐个校验 `phondata / phonindex / phontab / intonations / cmn_dict`，缺文件直接判失败
- 合成走 `AUDIO_OUTPUT_SYNCHRONOUS`，回调里攒 PCM，一次返回一句，播放由 App 用 `AudioTrack` 控制
- 逐句播放，句子边界就是进度点和暂停点；暂停 = 改标志位，音频线程自己收尾
- 语速映射到 eSpeak 的 wpm（175 × 倍率，80~450），音调映射到 0~99（50 为基准）

### v1.6.3 修的两处硬伤

1. **`espeak_Initialize` 带 `espeakINITIALIZE_DONT_EXIT`**。espeak 内部初始化失败时默认会调
   `exit(1)`（`espeak_api.c`），在 App 里等于瞬间杀进程，Java 层的崩溃兜底连堆栈都留不下——
   表现就是"点了听书没声音、紧接着闪退"。现在传 `DONT_EXIT`，失败只返回负数，转成界面提示。
2. **音频线程收敛到一根线程**。以前 `pause()` 会从主线程对正在 `write()` 的 `AudioTrack` 调
   `stop()/release()`，是典型的 use-after-free 闪退源；同时 espeak 也不是线程安全的，初始化在
   协程池 A 线程、合成在 B 线程也可能踩坏内部状态。现在全部 espeak 调用与 AudioTrack 操作都在
   `tts-audio` 单线程上，暂停只改一个 `volatile` 标志，写完小片段后自己收尾。

另外补了**英文词典 `en_dict`**（正文里夹英文单词、网址时不再反复报 `Can't read dictionary file`），
以及**落地日志**：每走一步写一行到 `filesDir/tts-trace.txt`，设置 → 关于里有「听书自检」和「日志」，
手表连不了 adb 也能自己定位卡在哪一步。

### v1.6.4 修的三处听感问题

1. **逐句合成 → 按段落块合成（约 300 字一块）**。旧实现每句一次 `espeak_Synth`、一次
   `AudioTrack` 创建销毁，每句话都从零起调，句间还夹一次建轨开销，听感一顿一顿、吐字发飘。
   整块交给 espeak 后，句子之间的停顿和语调由它自己处理，连贯性接近正常朗读。
2. **排空等待算错，凭空多出等长静音**。旧代码写完 PCM 之后又等了一整块时长，
   而阻塞式 `write` 本身已经按实时速度推进 —— 于是每块之后空出和正文一样长的静音，
   听起来正是"读完一段就没声音了"。现在只补足 `总时长 − 已过去时间`。
3. **自动续章**。`ttsAutoNext` 以前只有存储字段，没有任何地方读它。现在播放器通过
   `ChapterSource` 在读完一章时自己取下一章，正文页面跟着翻；设置 → 语音听书 也补了开关。

另外给块首块尾加了 6ms 淡入淡出（去掉切块处的"啪"声），中文语速基准从 175 降到 170 wpm。

### v1.6.5 双引擎 + 续播定位

eSpeak 的中文是**按词**合成的（实测 15 字出 8 个发声段），逐词短促停顿是共振峰合成的
固有节奏，调参调不出来——这就是"一个字一个字"的来源。要么换引擎，要么接受。

- **系统语音优先**：新增 `SystemTts`（`android.speech.tts`）。手表 ROM 自带中文语音引擎
  （讯飞/出门问问等）时音色接近真人，且零体积。设置 → 语音听书 → 朗读引擎：
  `自动`（有系统语音就用）/ `系统语音` / `内置 eSpeak`。系统引擎不出声时自动回退内置引擎。
- **续播定位**：以前暂停记住的是"第几块"，续听会把这一整块（约 1 分钟）从头再念一遍。
  现在 eSpeak 路径按**采样偏移**续播，接着刚才那句往下读；系统语音路径把块切到 90 字，
  粒度约 20 秒。
- 自检里加了词典判定：合成一句 15 个字，数发声段。段数≈字数说明词典没生效（逐字念），
  段数明显更少说明按词合成正常。

### v1.6.6 内置音色可切换

eSpeak 自带 104 个共振峰变体，实测同一句话基频差异明显：

| 音色 | voice spec | 基频 | 时长 |
|---|---|---|---|
| 标准男声 | `cmn` | ~120Hz | 3.6s |
| 低沉男声 | `cmn+m3` | 99Hz | 3.6s |
| 沉稳男声 | `cmn+m7` | 100Hz | 3.6s |
| 女声 | `cmn+f3` | 199Hz | 3.6s |
| 轻快女声 | `cmn+f1` | 172Hz | 3.6s |
| 低语 | `cmn+whisper` | 无基频 | 3.6s |

变体只改共振峰与基频，不改发音规则，所以吐字方式不变、只是音色不同。
入口：设置 → 语音听书 → 内置音色，附带「试听这个音色」。

### v1.7.0 本地导入（自动分章）

书架顶部「＋ 导入本地书」，选 txt 即可，导入后与网络书完全一致（可读、可听、进书架）。

- 编码三级回退：BOM → 严格 UTF-8（`CodingErrorAction.REPORT`）→ GB18030，覆盖 GBK/GB2312 老书
- 分章正则：`第[0-9零一二三四五六七八九十百千万两]{1,10}[章节回卷]`（含"第 2 章"带空格写法）、
  `Chapter N`、`序章/楔子/番外…`、`1、标题`；一条都匹配不到就按 3000 字切片
- 正文按 UTF-8 重写一份并记录**字节偏移**，阅读时 `RandomAccessFile` 随机读，几十 MB 不进内存
- 书籍 ID 由书名+文件大小+首字节算出，重复导入直接复用，不占两份空间

1.7 整体规划见 [`docs/PLAN-1.7.md`](docs/PLAN-1.7.md)：手机登录器、多站点聚合、性能优化、本地导入、在线 TTS。

## 十一、已知限制

1. **笔趣阁是第三方站点**：接口随时可能改版，解析失败时请在设置里做一次「检测书源可用性」，
   或者换回其它源。
2. **番茄只覆盖网页可见章节**：未登录只有前 10 章左右，App 会提示，不绕过。
3. **七猫没有正文**：只能浏览详情与目录。
4. **字体映射会过期**（番茄源）：番茄更换字体文件后书名会乱码，需重跑 `tools/gen_fontmap.py`。
5. **书架按书号去重**：不同源的书号偶有重复，同时收藏两本同书号的会互相覆盖（极少见）。
6. **听书音色偏机械**：内置引擎是 eSpeak NG，吐字清楚但没有真人感；换神经网络引擎会让 APK 涨到 50MB 以上。
7. 书架和进度只存在本地，不涉及账号体系。

## 2.3.0：在线语音换成百度接口

微软给 Edge「大声朗读」加了 `Sec-MS-GEC` 的 DRM 签名（自定义 CS64 + 改过常量的 SHA-256），
不带令牌一律 403。复刻那套签名既容易写错也挡不住再改，所以换成百度翻译的朗读接口：

- `GET https://fanyi.baidu.com/gettts?lan=zh&spd=5&source=web&text=...`，免 key、免签名，直接回 mp3
- 实测：150 字 → 302KB / 1.0s，300 字 → 604KB / 1.8s，连续请求不被限流
- 仍然走原来的缓存与播放链路（mp3 落盘、MediaPlayer 毫秒续播）
- 在线失败自动回退内置 eSpeak，不再让你干等

## 2.4.0：整章连续读 + 3 倍速 + 章节语音包

  块与块之间基本无缝。

## 2.6.0：右滑转场重做 + 两个站点的接口逆向

### ① 右滑返回不再是"整窗拖动"

旧实现把 `translationX` 挂在整屏根布局上、下层又没有内容，所以在定制 ROM 的手表上看起来
就是**系统在拖动整个应用窗口**。

现在按轻舟/watchOS 的做法：上层页面**缩小 + 轻微右移**，下面画的是"返回后看到的页面"。
实现要点：

- 压栈时用 `PixelCopy` 抓一张当前窗口快照，存进与导航栈对齐的 `belowStack`；
- 返回时先画这张快照（缩放 0.94→1、亮度 0.7→1），上层页面缩到 0.52 并淡出，动画结束才真正出栈；
- **不用 Compose 的 GraphicsLayer 录制**：那等于给整页加一层离屏纹理，每帧多渲染一遍，
  手表上会直接吃掉帧率；PixelCopy 只在真正要转场时抓一次，平时零开销；
- 动画值全部在 `graphicsLayer { }` 里读，拖动时只重绘、不触发重组；
- 抓不到快照（窗口未就绪/ROM 限制）时退化成只露背景，不会崩。

### ② nana00（娜娜阅读）接口
